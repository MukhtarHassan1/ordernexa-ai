# Security gates for external automation

**Do not expose the local localhost-only Operations Console to the internet.** `ORDERNEXA_ROLE_KEYS_JSON` is designed for the private portfolio demonstration, not production public hosting. Keep Windows Firewall restricted; `host.docker.internal` is local-to-Docker host routing, not an externally protected domain.

1. **Secrets:** Existing private `.env` must not be replaced, shared or added to ZIP exports. Generate unrelated 32+ character values separately for `N8N_INGEST_SECRET`, `GRAPH_CLIENT_STATE` and `VOICE_SERVER_SECRET`. Store `GRAPH_CLIENT_SECRET`, `HUBSPOT_ACCESS_TOKEN` and Teams workflow URL only in `.env` or enterprise secret storage. Rotate leaked credentials immediately.
2. **n8n:** Use n8n Basic Auth on the imported webhook, plus a *separate* n8n HTTP Header Auth outgoing credential named `X-OrderNexa-Ingest-Secret`. Leave the inbound n8n bridge local/private by default; n8n execution-history settings must not archive raw POs and secrets. n8n cannot directly perform ERP writes or govern approvals.
3. **Graph:** Administrator provisions a **dedicated tenant-scoped Entra app**, grants only required Microsoft Graph app permissions (`Mail.Read` for inbox; `Mail.ReadWrite` only for draft management; `Mail.Send` only when the human-approved sending feature is in scope; `Sites.Selected` for the specific authorized SharePoint site). Scope mailbox access using Exchange application RBAC/appropriate organizational mailbox restrictions; tenant-wide app roles may otherwise be broader than the project intends. Never grant general admin or all-sites access merely to simplify testing. Grant exact SharePoint site/drive access and record identity and expiry.
4. **Public webhook:** Microsoft Graph requires an externally reachable HTTPS URL to validate and deliver change notifications. A route-limited reverse proxy must allow ONLY `/api/v1/automation/graph/notifications` and `/api/v1/automation/graph/lifecycle`, enforce TLS and request-size/rate limits and forward to API without exposing `/console`, `/docs` or the rest of the app. The handlers verify Graph basic notification `clientState` and configured subscription ID; they **do not** implement rich notification JWT verification or full missed-message Graph delta resync. An endpoint callback alone does not certify authorization for production.
5. **External transfer:** The web operator must explicitly confirm business data transfer. Source documents should be minimized; the optional worker currently sends the *local verified confirmation* to one configured SharePoint drive. Never infer or invent a recipient email from PO text. HubSpot/Outlook require independently human-verified recipient email.
6. **Uncertain writes:** SharePoint uses deterministic item path + byte readback; HubSpot contact GET verification; Outlook draft GET verification. A Teams Workflows 2xx and Outlook send POST 202 are **acknowledgments**, not channel display or email delivery proof. A timeout after possible external POST must enter `BLOCKED_UNCERTAIN`: inspect remote system and reconcile, never auto-resend.
7. **Outbound customer email:** Creating a draft is not sending it. Only an authorized human may inspect a live draft, confirm exact recipient/content hash and explicitly release that **existing** draft with sending flags enabled. Validate Sent Items separately. An uncertain send is not retried automatically.
8. **Vapi:** Define tools for coarse `GET /api/v1/automation/voice/status/{public_id}` and review-only `POST /api/v1/automation/voice/change-request`; send server-only `X-OrderNexa-Voice-Secret`. Use a separately scoped public webhook route with TLS and caller-event dedupe. Customer phone number or spoken PO number alone is NOT proof of identity; voice may not edit bank, amounts, dates, customer or approve an order. A verified human reviews the queued change request.
9. **AI:** Retrieved docs and source email attachments are untrusted evidence; prompts cannot set price or select an ERP write endpoint. Raw model confidence is unreliable. Review any source conflict; enforce deterministic policy just before side effects. User's demonstrated Qwen result on one PO does **not** meet the blueprint's 97% critical-field release target.
10. **Production gap:** Proper OAuth/OIDC identity, tenant-level authorization, CSRF/security headers on publicly accessible frontend, rate limits, full threat assessment, audit retention, GDPR/compliance review, multi-worker failure tests, complete Graph delta reconciliation and controlled backups/restore are still required before a real client deployment.
